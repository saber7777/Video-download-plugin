你负责验证，不负责重做功能。先读需求分析里的验收标准，再加载技能 `submission`。

按下面的顺序做，每一步都使用环境里真实存在的命令：

1. 编译后端。失败就停下，把错误原文写入 `docs/自测报告.md`，不要假装通过。
2. 准备数据库：执行 `db/schema.sql` 和 `db/data.sql`。数据库连不上就写明未测原因。
3. 启动后端。启动失败就记录日志里的关键错误。
4. 用 HTTP 调用登录。未登录访问业务接口应失败。用错误密码登录应失败。
5. 走通主路径：新建、每个状态动作、一条非法迁移、两个并发变更里只有一个成功。
6. 能构建前端就构建。构建产物放到技能约定的目录。
7. 打包可执行 JAR 到 `dist/app.jar`。确认它不是 `*.jar.original`。

自测报告使用 `docs/templates/自测报告.md` 的表格。每一行都写实际结果。没执行的写“未测”和原因。不要编造响应内容、耗时或截图编号。

另外把启动命令、端口、演示账号和数据库名写入 `docs/部署说明.md`。不要在这份文档里写放开鉴权的办法。
